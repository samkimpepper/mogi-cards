101–102행 · 객체 만들기와 목록에 넣기
cur = {...}는 새 dict를 만들고, append(cur)는 그 dict의 참조를 목록에 넣어. 목록이 딕셔너리의 복사본을 갖는 것은 아니야.

113행 · 같은 객체 안의 집합 변경
cur["kw"].update(...)는 기존 set에 단어를 더해. cur를 다른 객체로 바꾸는 문장이 아니야.

109–110행 · 수집 상태만 변경
빈 줄에서는 in_goal = False만 실행해. 이 분기에는 cur를 지우거나 바꾸는 대입이 없어.

다음 제목에서 101행 재실행
cur가 새 dict를 가리키게 돼도, 목록의 0번 칸에 남은 참조는 이전 dict를 계속 가리켜.

재현에서 생략한 부분과 확인 범위
  • 문서 입력은 테스트 픽스처의 21–27행에 해당해. 원본 테스트 파일에서는 scripts/test-playbook-hint.sh:81–87이야.
  • words(), 조사 제거, STOP·GENERIC 제외는 실행 화면에서 생략했어. 원본 helper를 로컬에서 실행해 이 예시의 제목·검색 단어와 같은 값을 만드는지 별도로 대조했어.
  • 문서 23행에서는 수집을 켜고, 24행에서는 이미 있는 ‘실비청구’를 다시 더해. 재현은 값이 달라지는 25행의 추가만 남겼어. 새 제목에서 원본은 바로 in_goal=False로 두지만, 재현 7–8행 시점에는 앞서 False로 바뀐 값이 유지돼.
  • 이 화면은 객체 참조·집합 변경·수집 상태를 보기 위한 거야. 일반 절 제외, 목표 표현 추출, 관련성 점수, 안내 출력, Bash 고장 사본 비교는 실행하지 않아. 고장 사본 비교는 원래 노트 4절의 판정 표를 보면 돼.
