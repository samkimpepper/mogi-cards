## 처음 막힌 지점

SCRATCHPAD에서 PR 본문의 동작 표는 좋다고 평가하면서도, 어떤 파일·함수가 호출되는지와 설정 담당 위치가 보이지 않아 추상적으로 이해하는 것 같다고 밝혔다. Notes·checklist·reminder가 AppleScript·Things URL·내부 DB와 어떻게 연결되는지도 질문했다.

후속 문답에서는 `prepareNotesVerification()`이 왜 필요한지, `buildThingsAddUrl()`과 update/create를 나눠 맡는 관계인지 질문했다. 이는 함수 역할과 요청·확인 경계를 설명해야 하는 지점이며 개인 수준의 원인으로 해석하지 않는다.

## 설명 추가 없이 바로 연결한 지점

- 모기는 고정된 파일 이름이 그 자체로 나쁜 것은 아니며 지금 단계에서 경로 결정을 옮기는 리팩토링은 과할 수 있다고 의견을 냈다.
- 모기는 인자 개수 자체와 실행 보안 문제를 구분해 재진술하고 환경변수·심볼릭 링크로 실행 대상을 바꿀 수 있는지 질문했다. 과외냥이는 누가 환경·파일을 통제할 수 있는지의 조건과 셸 없이도 생기는 경로 검색 문제를 보충했다. 조건까지 처음부터 독립적으로 완성했다고 기록하지 않는다.
- SCRATCHPAD에는 리뷰 코멘트를 읽고 “Someday로 옮겨지징낳았는데도 인자가 verified가되는문제”라고 스스로 연결한 원문이 있었다. 실제 알림·프로젝트 보존 등 미확인 범위 전체를 이해한 것으로 넓히지 않는다.

## 설명·외부화 뒤 달라진 점

기존 할 일의 Someday 이동을 구체 제목·ID의 주인·호출 주체로 따라가는 텍스트 호출 트리와 설정 담당 표, 연결 코드 몇 줄을 보였다. 모기는 “방금 설명 뭔가 느낌좋고 맘에들어”라고 평가하고 답변 원문을 노트로 보존해 달라고 요청했다. 이후 “call stack tree 만들어준거 너무좋다”, 구체 예시와 설정 담당 표가 좋다는 반응도 명시했다. [보존 노트](../code-diff-notes/mogi-productivity/2026-10-22-pr44-someday-call-flow-and-settings.md)에 답변 본문을 그대로 저장했다.

Notes·checklist·시간 지정 경로를 펼친 뒤에는 함수 두 개의 역할, 미지원 기능, URL 수정 토큰, evening의 DB 확인에 질문이 이어졌다. 과외냥이는 Notes 비교 기준 준비와 생성 URL 구성을 대조하고, 새 생성에서도 둘 다 실행됨을 작은 흐름으로 보충했다. AppleScript·URL의 지원 차이, 브릿지 미구현 범위, 쓰기와 쓰기 후 확인을 구분했다. 이 보충 뒤 전체 코드 독해가 완료됐다는 독립 재진술은 관찰하지 않았다.

모기는 복잡함과 리팩토링 필요 여부를 질문했고, 과외냥이는 외부 API 제약·구현 선택·미구현 기능·설명 방식의 영향을 나눴다. 모기 요청으로 그 답변 원문을 `master-delivery-memos.md`에 보존·전달했다. 투두냥은 PR #44 머지 뒤 별도 PR에서 동작 계약부터 검토하고 리팩토링 범위를 정하는 후속 작업 `td-0fd`에 인수했다고 회신했다. 구현·검증 완료 보고는 아니다.

## 마지막 설명의 직접 확인 근거

제품 checkout은 읽기 전용으로 유지했다. 판독 SHA의 `integrations/things/`와 `package.json`을 저장소 밖 임시 폴더에 복사하고 아래 기존 시험을 실행했다. `notes.test.js`는 `execImpl` 모의 응답으로 Things 읽기·쓰기를 대신하므로 실제 앱을 호출하지 않는다.

```sh
node --test --test-name-pattern='Someday (create|reuse)' integrations/things/test/notes.test.js
```

- 정상 사본: 관련 시험 7개 통과, 실패 0, 건너뜀 0, 종료 코드 0.
- 고장 사본: `src/write-verification.js:76`의 `value.scheduled === wantedDate && (!someday || value.someday)`를 `value.scheduled === wantedDate`로 바꿔 소속 조건만 제거했다. 시험 파일은 바꾸지 않았다.
- 같은 시험 재실행: 5개 통과·2개 실패, 건너뜀 0, 종료 코드 1. create/reuse 각각의 `a move left outside Someday reports mismatch, not verified`가 actual `verified`, expected `mismatch`로 실패했다.
- 이 실험은 현재 시험이 해당 확인 조건 제거를 잡는다는 근거다. 원래 구현 당시 고장 심은 시험을 했다거나 모든 버그를 검출한다는 근거가 아니다.
- 실제 Someday 목록 이동, 알림 해제·실제 알림 발생·프로젝트 소속 유지는 이 모의 시험에서 확인하지 않았다. 임시 폴더는 종료 때 삭제했다.
