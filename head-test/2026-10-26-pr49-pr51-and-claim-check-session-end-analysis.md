## 짧은 기록

- **처음 막힌 지점:** #49에서 수동 lock 파일과 OS 잠금, 서로 다른 잠금이 필요한 상황, Bear 비교가 이루어지는 재시도 상황과 노트 동일성 기준을 물었다. #51에서는 한꺼번에 펼친 호출 트리 대신 몇 단계로 나눠 달라고 했고, 현재 시험 결과와 아직 작성하지 않은 보강 시험의 기대 결과를 과외냥이가 섞어 설명해 재확인이 생겼다. 노트의 퀴즈에서는 Notes를 미리 읽는 목적, import와 함수 호출의 차이, 구현에 덜 결합한 시험의 관찰 대상을 다시 물었다. #14의 첫 설명은 “별도 에이전트”라고 뭉뚱그려 말해 상시 실행 세션·서브에이전트·Orca 워커·일회성 CLI 프로세스가 구분되지 않았다. 모기는 특히 AI 실행 전의 기계적 조건을 물었는데 과외냥이가 AI의 판정 과정을 먼저 반복해 질문의 초점을 늦게 맞췄다.
- **설명 추가 없이 바로 연결한 지점:** #49에서 공용 파일을 없애는 설계 대안을 제시하고, 줄바꿈 차이를 엄격히 구분할 필요가 있는지를 사용자 의도로 되물었다. #51에서는 테스트가 서비스 내부 함수들을 그대로 따라 부르면 결합이 커진다는 점과 `parseDays`가 교체되는 경우를 스스로 질문했다. 노트 답변에서는 조회만으로 수정되지 않는다는 점, 기대한 예외와 테스트 통과의 차이, 고장 사본의 시험 통과가 탐지 공백을 드러낸다는 방향을 설명했다. Notes 보존 검사의 목적을 설명받은 뒤에도 실행마다 비교할 비용까지 필요한지를 따로 질문했다. #14에서는 앞 턴 근거를 허용하는 문구의 필요성을 물어 검사 규칙의 경계를 짚었다. 앞선 설명·노트가 있는 상황의 연결이며 도움 없는 독립 해결 횟수로 세지 않는다.
- **설명·외부화 뒤 달라진 점:** #49의 버전 2 설명을 훨씬 이해하기 좋다고 보고했다. #51은 입구만 보여준 작은 지도 → readUpcoming/addTodo 나란히 → 공용 날짜 계산 순으로 펼친 뒤 “아우 지금 너무좋다. 진짜 대박~”, “ㅇㅇ 이해됨ㅋ”이라고 했다. 자유 메모 일곱 곳을 요청대로 주관식 다섯 개·연습 리뷰 댓글 두 개로 바꾸자, 모기는 답변을 작성하며 2·3·6번의 미연결 지점을 드러냈다(3·6번에는 모르겠다는 표시). import는 실제 파일 세 곳과 SQLite까지 이어지는 연결을 본 뒤 “모듈불러오는곳도 딸려오는것이군”이라고 재진술했다. 6번은 실패 종료·범위 오류·외부 조회 없음이라는 관찰 조건을 구체화한 뒤 질문을 이해했다고 말했다. #14에서는 검사마다 새 프로세스를 실행하되 매번 최근 세 턴을 전달한다는 표, 그리고 답장 내용의 사전 선별 없이 기계적 조건을 통과하면 AI 검사를 실행한다는 설명 뒤 “완전이해했어”라고 했다. 각 반응을 PR 전체 독해·일반 기억력·지연 후 적용 성공으로 합치지 않는다.
- **아직 미관찰이거나 다음에 확인할 점:** 노트를 보면서 작성한 답변과 그 후 설명은 관찰했지만 보조물 없는 새 사례의 독립 적용·지연 후 유지·IDE에서의 실제 독해 수행은 미관찰이다. 퀴즈는 이번에 모기가 선택한 구체 질문 자리로서 사용됐으며, 매 PR 의무화나 자유 문답보다 우수하다는 결론은 없다. #14의 실제 훅 연결·오탐·누락·생활 부담 감소는 이번 과외에서 시험하지 않았다. 제품 후속은 아래 메모·전달 기록에 보존하며 자동 복습 과제로 만들지 않는다.

## 학습 마찰·재확인·새 발견

- #49의 줄바꿈 비교 질문은 이해 확인 실패가 아니라 “같은 노트”의 제품 기준을 되묻는 사건이었다. 관련 의도 확인·훅 아이디어와 연구의 한계는 [마스터 메모](../master-delivery-memos.md)에 남겼다. Ask or Assume?의 모의 사용자 실험과 실제 사용자 부담을 구분했고 새 하네스는 구현하지 않았다.
- #51의 Notes 퀴즈 후 모기는 “코드 규칙을 자세히파악해서 테스트해보고 … 제품코드에서 그부분걍빼도되지않아?”라고 물었다. 검사 목적과 검사 필요성을 분리해, 기존 Notes 미입력 보존 요구는 유지하면서 매 실행의 기준값 조회·사후 비교는 재검토하자는 메모를 남겼다. 기존 T40의 조회 검증 선택도 함께 적었다. 즉시 검사 삭제나 다른 검증 일괄 제거로 해석하지 않는다.
- #14의 핵심 재확인 원문은 “그 기준 자체는 기계적이잖아 그게궁금해”였다. 답장 내용으로 먼저 선별하는 코드가 없고, 세션·재진입·끄기 조건 등을 통과한 답장 종료 때 AI를 호출한다는 구분을 설명했다. 반복 질문을 개인의 컨텍스트 유지 문제로 귀속하지 않는다.
- #14 리뷰는 세 항목을 짧게 소개하고, 오래된 조회와 이후 상태 변경을 구분해야 한다는 프롬프트 지적 하나를 설명했다. 이어 앞 턴 근거 허용의 목적을 갱신 주기 사례로 설명했다. 모기는 실사용에서 문제가 생기면 바꾸는 쪽에 동의했고 퀴즈 없이 마쳤다. 긴 입력 자르기와 Bash 출력 연결의 수정 전체를 과외한 것으로 기록하지 않는다.
