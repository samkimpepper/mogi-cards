# 모기용 머가리 테스트 참가 가이드

이 문서는 테스트 문제를 만드는 사람용 설명서가 아니라, 실제 참가자인 모기가 무엇을 해야 하는지 적은 사용설명서다.

이 테스트는 IQ 검사나 의학적 진단이 아니다. 문단으로 읽을 때와 표로 외부화했을 때 조건·주체·시점 유지와 추론 양상이 어떻게 달라지는지를 가볍게 관찰한다.

## 한 줄 절차

데모로 조작만 연습한 뒤, 아직 읽지 않은 새 카드의 참가자 케이스를 받아 같은 브라우저의 러너에서 풀고, 끝이나 중단 시 실행 JSON을 저장한다.

## 1. 데모로 버튼만 연습하기

저장소에서 서버를 연다.

```bash
cd /home/mogi/code/swatch/mogi-cards
python3 -m http.server 8765
```

브라우저에서 아래 주소를 연다.

```text
http://localhost:8765/head-test/runner.html
```

`cases/policy-snapshot-demo.json`을 선택해 버튼과 제출 순서만 익힌다. PR #501은 이미 배운 소재라 결과를 측정값으로 쓰지 않는다.

앞으로 정식 측정도 같은 브라우저 프로필과 같은 주소를 사용한다. 시크릿 창, 다른 포트, `file://`를 섞으면 저장 origin이 달라져 전역 제시 순서 원장이 이어지지 않는다.

## 2. 정식 케이스는 마스터에게 맡기기

다음 미검토 카드를 직접 읽기 전에 마스터에게 아래처럼 요청한다.

> 내가 아직 읽지 않은 새 미검토 카드로 정식 head-test 케이스를 만들어줘. 참가자 케이스와 정답 키를 분리하고 validator까지 돌려줘. 나에게는 내용 설명이나 정답을 보여주지 말고 참가자 케이스 경로만 알려줘.

마스터가 준비할 것은 다음과 같다.

- 모기가 아직 읽지 않은 작고 독립적인 기능
- 참가자용 케이스 JSON
- 완료 후에만 사용할 reviewer-only 정답 키
- A/B의 역할과 난도가 대체로 동급인지에 대한 사람 검토
- validator 통과 확인

모기는 준비 중인 카드·PR·정답 키를 미리 열지 않는다. 참가자 JSON도 러너에 선택하기 전에 따로 읽지 않는다. 미리 내용을 보면 그 케이스는 더 이상 처음 보는 재료가 아니다.

## 3. 정식 측정 시작하기

1. 항상 같은 러너 주소를 연다.
2. 마스터가 준 참가자 케이스 JSON만 선택한다.
3. 정말 처음 보는 독립적인 재료라면 확인란을 체크한다.
4. `시작`을 누른다.

러너가 문단 또는 표 중 하나를 먼저 배정한다. 모기는 순서를 고르거나 바꾸지 않는다.

초기 블록은 두 개다. 각 블록은 별도로 4~5분을 받고 다음 네 종류에 답한다.

- 사실 회상
- 상태 추적
- 새 사례 추론
- 모순 탐지

첫 블록의 네 답을 모두 잠가야 두 번째 블록이 열린다. 두 번째 블록에도 새로운 4~5분이 주어진다.

## 4. 모를 때와 중단해야 할 때 구분하기

단순히 답을 잘 모르겠다는 이유로 중단하지 않는다. 현재 이해대로 답한 결과 자체가 관찰 대상일 수 있다.

아래 상황에서는 내용을 더 설명받기 전에 `입력 결함·내용 도움 신고`를 누른다.

- 누가 무엇을 뜻하는지 주어가 빠졌다.
- 어느 값이나 테이블인지 출처가 빠졌다.
- 필요한 답이 선택지에 없다.
- 규칙끼리 실제로 모순된다.
- 카드 밖 지식이 있어야만 답할 수 있다.
- 다른 사람이나 AI에게 내용 설명을 받았다.

이 실행은 모기의 오류로 채점하지 않고 무효 실행으로 보존한다.

같은 문장을 반복해서 읽거나 더 진행하기 어려울 정도로 피곤하면 `여기서 중단`을 누른다. 시간 초과도 실패 판정이 아니라 별도의 incomplete 실행이다.

중단·무효·시간 초과된 동일 케이스를 정식 측정으로 다시 풀지 않는다. 이미 내용을 보았으므로 다음 측정에는 새 카드가 필요하다.

## 5. 지연 구간 보내기

초기 두 블록 뒤에는 화면에 표시된 해제 시각까지 다른 주제를 본다. 보통 약 5분이다.

이때 다음 행동은 하지 않는다.

- 원본 카드나 PR 다시 보기
- 참가자 JSON 열기
- 정답 키 보기
- 방금 규칙을 다른 사람이나 AI에게 묻기

잠금이 풀리면 먼저 요약 없이 답한다. 그 답을 잠근 뒤에만 표를 보며 두 번째 지연 질문에 답한다.

현재 지연 구간은 기억 간격과 직전 회상 연습이 섞여 있다. 따라서 `표 때문에 성능이 좋아졌다`는 인과 증거로 쓰지 않고 참고 관찰로만 본다.

## 6. 완료하거나 중단한 뒤 저장하기

종료 화면이 뜨면 먼저 `실행 JSON 저장`을 눌러 원답을 보존한다.

정상 완료한 경우에만 reviewer-only 정답 키를 선택한다. 그러면 짧은 구조 입력의 문항별 exact match가 계산된다. 키를 적용한 뒤 JSON을 다시 저장하면 계산 결과도 함께 들어간다.

자유서술과 모순 탐지의 의미는 자동 채점하지 않는다. 저장한 실행 JSON을 과외냥이나 마스터에게 주어 아래를 사람이 검토한다.

- 조건·주체·시점을 잃은 오류가 있었는가
- 변경 전후 값을 뒤집었는가
- 새로운 모순이나 입력 결함을 발견했는가
- 코드베이스 비숙련이나 문제 품질로 설명되는가
- 문단과 표 조건에서 어떤 차이가 있었는가

실행 JSON을 저장소에 남기고 싶으면 `head-test/runs/`에 기록하고 커밋해달라고 요청한다. 러너가 저장소에 직접 쓰지는 않는다.

## 7. 결과를 어디까지 믿을 수 있는가

한 번의 실행으로 모기의 지능·인지능력·의학적 상태를 판단하지 않는다.

서로 다른 처음 보는 카드가 최소 두 개 쌓였을 때 다음 패턴이 반복되는지를 본다.

- 문단 조건에서 조건·주체·시점을 더 자주 잃는다.
- 표 조건에서 새 사례 추론이나 모순 탐지가 회복된다.
- 표가 있어도 같은 종류의 규칙 적용 오류가 계속된다.
- 실제 원인은 모기가 아니라 문제의 빠진 주어·출처·선택지였다.

입력 결함, 내용 도움, 피로 중단, 시간 초과가 섞인 실행은 효과 판정에서 제외한다. 질문을 많이 했다는 사실만으로 이해력이 낮다고 채점하지 않는다.

## 시작 전 체크리스트

- [ ] 같은 브라우저와 `http://localhost:8765`를 사용한다.
- [ ] 원본 카드·PR·정답 키를 아직 읽지 않았다.
- [ ] 참가자 케이스를 따로 열지 않고 러너에서만 선택한다.
- [ ] 피곤하지 않고 초기 8~10분과 지연 시간을 확보했다.
- [ ] 입력 결함이나 내용 도움은 즉시 신고한다.
- [ ] 끝이나 중단 뒤 실행 JSON을 저장한다.
- [ ] 한 번의 결과로 결론 내리지 않는다.
