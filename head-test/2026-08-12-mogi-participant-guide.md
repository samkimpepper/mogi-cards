# 모기용 이해 관찰 간단 가이드

이건 시험 응시 설명서가 아니다. 평소처럼 카드를 공부하면서 어떤 방식이 이해에 도움이 되는지 보는 가이드다.

## 모기가 기억할 네 가지

### 1. 실제 diff부터 본다

긴 배경 설명보다 코드에서 무엇이 바뀌었는지 먼저 본다. 핵심을 한 문장으로 말하기 어렵다면 과외냥이에게 먼저 풀어달라고 한다.

### 2. 마음대로 질문한다

용어, 주어, 값의 출처, 문장의 의도를 전부 물어봐도 된다. 질문이 많다는 사실은 오답이나 낮은 이해력의 증거가 아니다.

문서가 이상하거나 필요한 전제가 빠졌다고 느끼면 그대로 지적한다.

### 3. 이해한 뒤 새 사례 하나만 본다

더 확인하고 싶을 때만 과외냥이에게 이렇게 말한다.

> 방금 이해한 규칙을 적용할 작은 새 사례 하나만 줘.

시간 제한은 없다. 피곤하거나 더 하고 싶지 않으면 하지 않는다.

### 4. 넓은 결론을 내리지 않는다

세션 끝에는 이것만 남긴다.

- 처음 막힌 지점:
- 설명·표·코드 뒤 달라진 점:
- 아직 모르거나 다음에 확인할 점:

한 번 막혔다고 모기의 지능이나 인지능력을 판단하지 않는다. 코드베이스 비숙련, jargon, 문서 품질, 설명 방식과 피로를 먼저 구분한다.

## 기계식 러너

기존 HTML A/B 러너는 선택적 실험 도구로만 남아 있다. 평소 카드 공부에는 열지 않아도 된다.

모기가 나중에 통제된 실험을 **명시적으로 다시 하고 싶을 때만** [`README.md`](./README.md)를 읽고 사용한다.
