## 2. 이번 구간의 결론

**구현 방법보다 사건의 목적을 먼저 연결하고, 실제로 실행하는 대상과 대신하는 대상을 구분할 때 문답이 이어졌다.** 표나 설명량 자체보다 그 표의 값이 왜 필요한지 드러내는 것이 중요했다. PR #11에서는 story-first가 밀렸다는 정정이 있었고, PR #60에서는 누락 검사의 목적을 가까이 설명한 뒤 이해 반응이 있었다. 지침이 있다는 사실만으로 항상 잘 적용됐다고 판단하지 않는다.

모기는 필요한 학습 형식을 직접 골랐다. PR #51에서는 자유 메모를 구체적 퀴즈로 바꾸길 원했고, 다른 PR에서는 퀴즈를 생략하거나 직접 요약했다. 마지막에는 테스트 코드를 읽고 과거 ATDD 경험과 현재 경우별 리뷰를 연결했다. 이를 모든 세션의 테스트·퀴즈 의무화로 바꾸지 않는다.

앞선 누적 검토의 “질문 범위와 필요한 전제를 가까이 밝히기”, “관계에 맞는 표현 선택”은 계속 유효한 사용성 근거가 있다. 그러나 목적·가정이 빠진 설명을 표만 추가해 해결한 것으로 보지 않는다. Spring 비유는 익숙한 출발점이었고, 실제 프로세스 경계와 테스트 서버 종류가 다를 때 차이도 함께 설명해야 했다.

### 모기의 자기조절

모기는 story-first를 다시 요구하고 잘못 추측한 의도를 교정했다. 보안 구멍을 계속 막는 비용과 upstream 이력 차이의 비용을 고민하며 범위를 줄였고, 피로할 때 간략한 설명을 골랐다. 후반에는 흥미가 생긴 테스트 구조를 자발적으로 더 읽었다. 이 선택은 각 시점의 학습·작업 범위 조절이며 성격이나 기술적 판단의 보편적 정확성으로 평가하지 않는다.

### 새 사례 적용

별도의 값·이름을 바꾼 독립 적용과 지연 후 유지 시험은 미관찰이다. PR #51 답안, 실행기 퀴즈 재진술, ATDD와 경우별 리뷰의 연결은 앞선 설명·자료가 있는 맥락의 관찰로 보존한다. 테스트 독해의 즐거움을 독립 설계 성공으로 바꾸지 않는다.

## 5. 다음 세션에서 실제로 바꿀 것

당분간 기존 지침·도구를 활용하고 새 하네스·설명 도구를 추가하지 않겠다는 기존 요청을 유지한다. 이후 명시적으로 요청받는 한정 작업과 구분한다.

1. **현재 질문의 사건·기대 결과·목적을 먼저 붙인다.** 검사 목록이나 코드 값이 나오면 왜 그것을 확인하는지 같은 대목에서 연결한다. 사용자의 의도를 먼저 합리화하지 않고 선택지의 실제 차이를 설명한다. 필요한 코드 몇 줄·표·호출 지도 중 하나를 골라 질문 범위 안에서 쓴다.
2. **테스트 설명에서는 실제로 움직이는 것과 대체한 것을 가까이 밝힌다.** 서버·외부 앱·프로세스·가짜 파일 각각의 역할을 구분하고 응답과 부작용의 관찰을 연결한다. Spring 비유는 대응과 차이를 함께 설명한다. 테스트 독해·직접 실행·작성자 보고·새 사례 적용을 구분하며 테스트 공부를 매 PR의 의무로 만들지 않는다.

효용이 관찰된 사건 설명·작은 호출 지도·비교 표만 인수한다. 성격·인지 가설이나 미관찰 항목 해소용 퀴즈는 추가하지 않는다.
