# 기계식 머가리 테스트 러너 코드·측정 타당성 리뷰

날짜: 2026-08-12

리뷰 대상: 커밋 `b93056b`

리뷰어: `gpt-5.6-sol`, reasoning effort `high`, 읽기 전용 서브에이전트

## 판정

`NEEDS_FIX_BEFORE_PILOT`

현재 구현은 정상 UI 경로에서 단계 순서·시간·피드백 표시를 잠그는 워크플로 데모로는 유용하다. 그러나 문단 조건과 표 조건의 효과를 비교하는 정식 pilot 전에 순서 배정, 지연 검사 해석, 정답 분리, 부분 시행 기록, 저장 상태 검증을 고쳐야 한다.

## BLOCKER

### 1. 서로 다른 새 카드 사이에서 제시 순서가 균형화되지 않음

순서 기록이 케이스 ID별이라 처음 보는 새 카드는 매번 `문단 → 표`로 시작했다. 같은 ID를 다시 실행하면 순서는 뒤집히지만 재료가 더는 낯설지 않다. 파일을 불러오기만 해도 순서 기록을 소비하므로 중단·무효 실행이 유효 실행의 순서 배정까지 흔들 수 있었다.

또 초기 두 블록이 하나의 제한시간을 공유해 두 번째 조건은 남은 시간만 받았다. 이 상태에서는 표현 형식 효과와 연습·피로·시간 압박을 분리할 수 없다.

수정 방향: 서로 다른 케이스 전체에서 전역 순서를 배정하고, 실제 시작할 때만 배정을 확정하며 모든 배정·제외를 기록한다. 블록별 제한시간도 동일하게 둔다.

### 2. 지연 검사가 표 지원의 인과효과를 식별하지 못함

요약 없는 지연 문제는 항상 먼저 본 A 변형이고, 표가 있는 지연 문제는 나중에 본 B 변형이었다. A는 기억 간격이 더 길고, B는 직전 무지원 회상이 연습으로 작용한다. 변형·기억 간격·검사 순서·표 지원이 분리되지 않는다.

수정 방향: 독립 동형 문항이나 별도 counterbalanced 세션을 설계하기 전에는 지연 구간을 인과 비교가 아닌 서술 관찰로만 표시한다.

## MAJOR

### 3. 완료 전 정답 잠금이 UI 수준에 그침

`expected` 값이 참가자가 직접 고르는 케이스 JSON과 localStorage에 처음부터 들어 있었다. UI가 채점 화면을 숨겨도 파일이나 저장 상태에서 정답을 볼 수 있었다. 외부 설명을 받아도 정상 완료 실행으로 남는 문제도 있었다.

수정 방향: 참가자 케이스와 reviewer-only 정답 키를 분리하고, 외부 도움·내용 설명이 들어오면 실행을 무효화하는 경로를 둔다. 브라우저가 외부 도움까지 막지는 못한다고 명시한다.

### 4. canonical 모델이 의미적·인지적 동형성을 보장하지 않음

validator는 규칙 수, 표 셀 존재, 토큰 키와 템플릿 골격만 검사했다. 문단과 표는 별도 작성이라 서로 모순돼도 통과하며, A/B 토큰은 같은 의미 역할인지 검증하지 않았다.

수정 방향: 한 typed fact model에서 문단과 표를 모두 렌더한다. 토큰 역할을 명시하고, 실제 인지 난도 동등성은 사람의 블라인드 검토가 필요하다고 표현을 좁힌다.

### 5. 답할 수 없는 케이스도 validator를 통과함

구조 입력이 0개인 질문, 중복·비문자열 선택지, 선택지에 없는 expected, DOM ID 충돌 가능성을 허용했다.

수정 방향: 질문마다 최소 입력 하나, 안전하고 전역 충돌 없는 ID, 고유 문자열 선택지, 정답 키의 expected가 실제 선택지에 포함되는지를 검사한다.

### 6. 부분 응답과 미시행을 구분하지 못함

블록을 보고 일부 답한 뒤 중단해도 최종 제출이 없으면 `not_administered`로 기록했다. 실제 미노출 블록과 노출·부분 응답 블록이 섞였다.

수정 방향: `submitted`, `partial_draft`, `presented_no_submission`, `not_presented`를 별도로 내보낸다.

### 7. 실행 덮어쓰기와 저장 상태 위조를 막지 못함

활성 실행 중 새 케이스를 고르면 기존 답변이 덮어써졌다. localStorage 복구 시 케이스만 검사하고 단계·전이·deadline·case binding은 검사하지 않았다. append-only는 정상 core 호출 안에서만 성립했다.

수정 방향: 활성 실행 교체를 거부하고, 실행별 ID로 저장하며, 복구 전에 세션 구조·전이 연속성·케이스 결합·시간 값을 검증한다. 기록은 암호학적 무결성이 없는 로컬 이력이라고 정직하게 명시한다.

## MINOR

### 8. 전체 exact 합계는 A/B 효과 점수가 아님

필드가 네 개인 상태 추적 문항이 필드 하나인 추론 문항보다 네 배 가중되고, 초기·지연 결과까지 합쳐졌다. 이 합계로 문단 대 표 효과를 추정할 수 없다.

수정 방향: 조건·문항별 원자료를 보고하고 자유서술은 블라인드 사람 코딩에 남긴다. 정당화되지 않은 omnibus 합계는 제거한다.

### 9. `file://` 저장 내구성과 접근성 경계

브라우저나 프라이버시 설정이 file origin의 localStorage를 막으면 저장이 실패할 수 있다. reasoning textarea의 label 연결과 동적 단계 안내도 부족했다.

수정 방향: storage 가능 여부를 감지하고 메모리 fallback·명시적 경고를 제공한다. label 연결, live region, 단계 전환 focus를 추가한다.

## 기계가 실제로 보장하던 것

- 정상 core 경로의 단계 순서와 종료 후 잠금
- 초기 제한시간과 지연 해제 최소시각
- 규칙 5개와 질문 종류 4개의 구조
- 같은 문자열 템플릿과 토큰 키를 사용한 A/B 렌더
- 정상 UI에서 완료 전 채점 화면 미표시
- 피로·시간 초과·신고된 입력 결함 뒤 상태 전이 차단
- core를 거친 draft·제출·전이 이벤트 누적
- 케이스 내용의 직접적인 HTML 삽입 방지

## 반영 상태

같은 날 아래처럼 수정했다.

- 같은 브라우저 origin의 정식 측정 케이스 전체를 대상으로 전역 교대 순서를 배정한다. 데모 배정은 원장에 남기되 균형 계산에서는 제외하고, 중단·무효·시간 초과·초기화도 outcome으로 기록한다.
- 초기 블록마다 독립적인 4~5분 제한을 새로 부여한다.
- 지연 결과에서 표의 인과효과를 계산하지 않고 혼입이 있는 서술 관찰이라고 내보낸다.
- 참가자 케이스와 reviewer-only 정답 키를 분리하고, 내용 도움을 받았다는 신고 사유를 추가했다.
- 한 typed fact에서 문단과 표를 모두 만들며 token role과 케이스·정답 키 입력을 더 엄격히 검증한다.
- 내보내기에서 제출·부분 draft·노출 후 미제출·미노출을 구분하고, 정당화되지 않은 전체 합계를 제거했다.
- 활성 실행 덮어쓰기를 거부하고 저장 세션의 케이스 결합·전이 연속성·답변 구조를 복구 전에 검사한다. 정식 시작 때 원장과 세션이 함께 저장되지 않으면 롤백하고 시작을 거부한다.
- localStorage 불가를 감지하고 정식 측정을 거부하며, label·live region·단계 전환 focus를 보강했다.

수정 뒤 Node 테스트 21개, core와 HTML 인라인 스크립트 문법 검사, 데모 케이스·정답 키 validator가 통과했다. 그래도 실제 인지 난도 동등성, 외부 도움 방지, 로컬 기록의 암호학적 무결성은 기계가 보장하지 않는다.
