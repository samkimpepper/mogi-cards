## 4. 현재 가설의 지지 증거와 반박 증거

현재의 좁은 가설은 “같은 `대표`가 발색 행·사진 사본·대표 행을 번갈아 가리키거나, 보호 규칙과 회수 규칙처럼 시점이 다른 조건이 한 문장에 겹치면 참조 복원 비용이 생기며, 실제 행·컬럼·이벤트 전후와 테스트의 판정 방향을 외부화하면 판단이 이어진다”이다.

### 지지 증거

1. **C1의 삭제 단위 분리:** 발색 행 전체 삭제와 `image_urls`에서 사진 한 장 제거를 분리한 뒤, 모기는 정상 도달 경로를 이해하고 “발색에서 뺐다는 사실을 더 우선”하는 정책을 직접 판정했다.
2. **C2의 사진별 관계 부재 외부화:** `swatch_media`가 `swatch_id`만 갖고 사진별 shade를 모른다는 구조를 제시한 뒤, 모기는 단독샷 손실보다 A에 B 사진이 박히는 오매핑 손해가 크다고 구체화했다. 동시에 입력 병목을 추가하지 않겠다는 과거 제품 원칙을 회상했다.
3. **C4의 값 적용:** 정상 A 매핑 하나와 해석 불가 slug 하나인 새 조합에서 모기는 `v_mapped=1`, `v_unresolved=1`을 답했다. 이어 중복 slug 참조 자체를 없앨 수 있는지 구조 개선 질문으로 이동했다.
4. **C5의 판정 방향 교정:** “IF는 성공 조건이 아니라 나오면 테스트를 터뜨리는 실패 조건”이라고 먼저 고정하자, 모기는 변경 전 성공 상태가 `manual + p1 유지`라는 것을 코드에서 다시 읽었다.
5. **C6의 작은 행 그림:** A 사진 행·A 좌표·제자리 URL 교체를 세 행으로 축소하자, 모기는 좌표 초기화라는 가능한 수리 방향을 제안했다. 이후 실제 코드 소비처 0개와 QA 행 0개를 확인해 현재 사용자 기능과 미래 정합 문제를 분리했다.

### 반박 증거

반박 증거는 0개가 아니다.

1. **C1은 질문 입력에 사용자 이벤트가 빠져 있었음:** “대표사진 원본 회수”만으로는 발색 행을 삭제하는지 사진 한 장을 수정하는지 고정되지 않는다. 재질문은 도달 경로를 명시하지 않은 설명 문제로도 설명된다.
2. **C2는 실제 제품 트레이드오프:** 다중-shade 발색 안의 유효 단독샷을 놓치는 손해와 sticky 오매핑을 막는 이익 사이에는 정답이 자동으로 나오지 않는다. 망설임은 조건 손실이 아니라 소유자 정책 판단이었다.
3. **C4는 실제 스키마 중복을 발견:** `shade_id`가 있는데 `shade_slug`도 저장하는 이유를 묻자 QA 실측과 이력이 필요했고, ID backfill 뒤 중복 참조 폐기라는 별도 개선 후보가 확인됐다. 용어 질문을 이해 실패로 볼 수 없다.
4. **C5는 SQL 테스트 관례의 입력 부족:** 실패 조건을 나열하는 `IF ... RAISE EXCEPTION` 패턴을 먼저 설명하지 않은 채 raw diff를 제시했다. 코드를 읽었지만 의미가 연결되지 않은 것은 핵심 판독 규칙 누락으로 직접 설명된다.
5. **C6은 실제로 미사용 스키마였음:** “우리 앱에 그런 기능이 있었나”라는 의심은 맞았다. `swatch_regions`는 초기 테이블로 존재하지만 앱 소비처와 QA 행이 모두 0이어서 현재 화면 기능으로 설명하면 부정확하다.
6. **명시적 피로 뒤 범위 축소:** C6 이후 다른 교차 리뷰 항목을 보지 않고 종료한 것은 모기가 밝힌 피로와 fix 워커 인계로 설명된다. 이를 유지 또는 전이 실패로 분류하지 않음.

### 잠정 판정

- **컨텍스트 구성 비용 가설:** 부분 지지. 행·컬럼·이벤트와 IF의 판정 방향을 명시한 뒤 재진술과 새 값 적용이 이어졌다. 동시에 여러 질문이 실제 설계 결함, 중복 스키마, 미사용 테이블을 발견했다.
- **외부화 효과:** 지지. `swatches.image_urls → swatch_media → shade_images` 시간선, 실패 조건의 역읽기, A 사진 행과 ROI 좌표 표가 각각 후속 재진술을 가능하게 했다. 표현 방식 간 통제 비교는 없음.
- **일반적 작업기억 저하 가설:** 지지 불충분. 새 `v_mapped/v_unresolved` 조합 적용, 정책 손해 비교, SQL 역조건 판독, 별도 스키마 정리 질문이 관찰됐다.
- **질문 횟수를 실패 지표로 쓰는 방식:** 반박됨. 질문이 manual 회수 비대칭, 다중-shade 오매핑, slug 중복 참조, 미사용 ROI 테이블을 구분하는 데 직접 기여했다.

| C6 | 이미지 정체성과 행 ID, 좌표의 의미를 결합하는 비용 | 중간 | 실제 앱 기능이 아닌 미사용 초기 스키마를 현행 기능처럼 소개한 범위 오류 | 높음 |

## 7. 짧은 종료 기록

- **처음 막힌 지점:** 발색은 남고 대표사진 한 장만 `image_urls`에서 빠지는 정상 경로, RPC 호출 권한과 `is_admin()`의 차이, `v_mapped/v_unresolved`의 정체, SQL 픽스처 IF의 판정 방향, ROI가 실제 앱 기능인지 여부.
- **설명·외부화 뒤 달라진 점:** 사진 제거가 manual보다 우선한다고 판정했고, 다중-shade manual 후보를 오매핑 방지 때문에 거부하는 결론을 냈다. 새 매핑 조합에서 두 변수 값을 적용했고, 실패 조건을 반대로 읽어 변경 전 `manual + p1` 잔류를 해석했다. A 사진·B 사진·좌표 관계로 ROI 오염을 이해하고 좌표 초기화라는 대안을 제시했다.
- **아직 모르거나 다음에 확인할 점:** 교차 리뷰 개정 2의 fix 워커 결과와 새 HEAD는 미관찰. `swatch_regions`를 장기적으로 유지할지 폐기할지는 별도 스키마 결정이며 현재 확정하지 않음. 경쟁 조건·지연 유지·동급 비교는 미관찰.
