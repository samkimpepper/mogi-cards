## 판정

**정식 head-test 판정 불가.** 이번 세션은 일반 과외로 진행됐고, [head-test 가이드](../guide-mogi-head-test.md)의 문단 조건·외부화 조건·동급 사례·지연 재검사를 미리 설계하지 않았다.

따라서 아래 내용은 가설을 확정하거나 반박하는 실험 결과가 아니라, 다음 정식 테스트에서 다시 확인할 **비통제 관찰 기록**이다.

## 프로토콜에서 빠진 것

- 같은 정보를 문단만으로 먼저 제시한 조건이 없음
- 같은 난도의 외부화 조건과 직접 비교하지 않음
- 사실 회상·상태 추적·새 사례 추론·모순 탐지를 독립적으로 측정하지 않음
- 이름과 값만 바꾼 동급 사례를 사용하지 않음
- 5~10분 뒤 요약 없이 재적용하고, 다시 표를 보며 재적용하는 지연 검사가 없음
- 소요 시간·재질문 횟수·조건 누락·역할 또는 시점 교환을 정해진 표에 기록하지 않음
- 설명·힌트·즉시 피드백이 계속 제공되어 독립 추론과 학습 효과를 분리할 수 없음

## 이번 세션에서 관찰된 것

### 1. 실행 순서를 외부화하자 최종 상태를 추적했다

처음에는 `seed.sql`이 마이그레이션보다 먼저 실행된다고 예상했다. 아래 순서를 계속 보이게 두자 권한의 최종 상태를 자기 말로 설명했다.

```text
마이그레이션 REVOKE
→ seed.sql blanket GRANT
→ seed 아래쪽 재-REVOKE
→ 최종 유효 권한
```

이어 “마이그레이션에 REVOKE가 적혀 있다는 사실만으로 실제 권한이 닫혔다고 결론낼 수 없다”고 답했다.

### 2. 검증 범위를 목록으로 외부화하자 누락 사례를 만들었다

CI가 실행하는 범위를 명시한 뒤, 초록불이어도 남을 수 있는 새 사례로 **동시성 관련 오류**를 바로 제시했다. 이는 SQL 검증 범위와 제외된 `.sh` 동시성 테스트를 구분한 적용이었다.

### 3. 익숙한 언어의 대응 관계가 숨은 도구 동작을 드러냈다

`events_rls_verify.sql`의 수리 전후를 아래처럼 대응시키자 차이를 즉시 설명했다.

```text
SELECT 결과 출력 ≈ System.out.println()
RAISE EXCEPTION 단언 ≈ assertFalse / assertEquals 실패
ON_ERROR_STOP ≈ 실패를 psql 종료 코드로 전달
```

처음에는 일반적인 미처리 exception처럼 `RAISE EXCEPTION`만으로 프로세스가 실패 종료할 것으로 예상했다. `psql`이 기본적으로 오류 뒤에도 계속 실행할 수 있다는 도구 고유 동작을 설명한 뒤, CI가 직접 보는 것은 종료 코드라고 답했다.

이 혼동은 짧은 인과관계 적용 실패라기보다 **처음 접한 `psql`의 기본 동작에 대한 지식 부재**로 설명할 수 있다.

### 4. 용어 경계를 바로잡은 뒤 관계를 다시 적용했다

처음에는 RPC의 “입력 인자”와 반환값을 비교한다고 표현했다. 입력 인자와 반환 JSON 키를 구분한 뒤에는 다음 계약을 설명했다.

```text
authenticated에게 SELECT 허용된 swatches 컬럼 집합
==
create_swatch·update_swatch가 반환하는 JSON 키 집합
```

또 공개 컬럼을 GRANT에만 추가하면 RPC 자체가 즉시 권한 오류를 내는 것이 아니라, RPC는 성공할 수 있고 **계약 비교 테스트가 집합 불일치로 실패시킨다**는 점을 교정 후 구분했다.

### 5. 간접 의존성을 함수 입력처럼 외부화하자 새 대상을 연결했다

워크플로 `paths`를 “CI 결과를 바꿀 수 있는 입력 목록”으로 설명한 뒤 다음을 연결했다.

- `seed.sql`이 빠지면 seed만 바꾼 PR에서 잡이 실행되지 않음
- 워크플로 자신이 빠지면 검사기를 바꾼 PR에서 새 검사기를 실측하지 못함
- README는 사람 행동에는 영향을 주지만 현재 CI 실행 결과의 직접 입력과는 구분해야 함
- README와 workflow에 긴 명령을 중복하면 두 정본이 어긋나는 유지보수 문제가 생김

## 관찰상 헷갈린 지점

| 지점 | 최초 반응 | 외부화·교정 뒤 |
|---|---|---|
| `seed.sql` 실행 시점 | 마이그레이션보다 먼저라고 예상 | 마이그레이션 뒤 실행과 최종 권한 상태를 설명 |
| RPC 계약 비교 대상 | 입력 인자와 반환값으로 표현 | SELECT 허용 컬럼과 반환 JSON 키로 구분 |
| GRANT만 갱신한 경우 | RPC 자체가 오류를 낸다고 예상 | 계약 비교 테스트가 불일치로 실패함을 구분 |
| `RAISE EXCEPTION` | 곧바로 프로세스 실패 종료라고 예상 | PostgreSQL 문장·psql·CI의 세 층을 구분 |
| CI 초록의 범위 | “로컬 테스트 통과”로 넓게 표현 | 마이그레이션+seed 적용 로컬 DB에서 SQL 20개 통과로 구체화 |

## 가설과의 관계

이번 관찰은 다음 예측과 **일관되지만 증명하지는 않는다.**

- 순서·주체·검증 범위를 계속 보이게 두었을 때 새 사례 적용이 빨라졌다.
- 생략된 실행 시점이나 도구 고유 동작이 밝혀지면 설명 직후 교정됐다.
- 여러 질문은 이미 명시된 조건을 반복해서 잃은 것보다, 문서가 생략한 실행 순서와 검증 경계를 확인하는 질문이었다.

반면 아래 이유로 외부화 효과의 크기는 판정할 수 없다.

- 외부화 전 동급 문제의 기준 성능을 측정하지 않음
- 설명과 정답 피드백이 함께 제공됨
- 같은 주제를 여러 번 다루며 학습 효과가 누적됨
- 지연 후 유지 여부를 확인하지 않음

## 세션 종료 기록

- 외부화 효과: **판정 불가** — 유리한 관찰은 있으나 A/B 조건 없음
- 가장 자주 난 오류: 숨은 실행 순서·도구 동작을 일반적인 경험으로 보완한 초기 가정
- 모기가 스스로 적용한 새 사례·유지보수 위험: CI에서 제외된 동시성 오류 사례, `paths` 의존성 누락 위험, README/workflow 중복 정본의 드리프트 가능성
- 모기가 스스로 발견한 입력 결함·모순: 이번 비통제 세션에서는 별도로 판정하지 않음
- 설명 직후 수정 여부: 관찰한 사례에서는 수정됨
- 지연 후 유지 여부: 미측정
- 코드베이스 비숙련이나 문서 품질로 설명되는 부분: `seed.sql` 실행 순서, `psql` 오류 처리, 카드의 압축 표현
- 다음 세션에서 다시 확인할 예측: 표나 실행 순서를 계속 보이게 둘 때, 동급 새 사례의 상태 추적과 모순 탐지가 문단 조건보다 좋아지는가

## 다음 정식 세션에서 할 일

처음 보는 작고 독립적인 카드로 20분을 따로 잡는다.

1. 규칙 5~7개를 긴 문단으로만 제시한다.
2. 사실 회상·상태 추적·새 사례 추론·모순 탐지를 각각 묻는다.
3. 같은 정보를 표나 상태 전이로 계속 보이게 둔다.
4. 이름과 값만 바꾼 동급 사례를 다시 묻는다.
5. 다른 주제를 본 뒤 요약 없이 한 번, 표를 보며 한 번 재적용한다.
6. 질문을 입력 결함 확인·조건 누락·새 모순 발견으로 나눠 기록한다.

최소 두 개의 서로 다른 새 카드에서 같은 경향이 반복되기 전에는 잠정 결론을 갱신하지 않는다.
