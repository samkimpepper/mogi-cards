## 2. 이번 구간의 결론

**주체·시점·값의 출처를 명시하는 것과, 지금 읽을 설명의 범위를 고르는 것이 함께
필요했다.** 빠진 정보를 채운다고 출처 표·용어·해설을 계속 덧붙이는 것만으로는
읽기 부담이 해소되지 않았다. 반면 필요한 관계를 한눈에 대응시킨 Git 상태표,
객체 참조 전후 표, 실제 할 일 하나를 따라간 호출 트리에는 각각 긍정 반응이 있었다.

구간 A에서는 원본·운영 저장소·실행 사본의 역할, Git의 시점별 브랜치 상태처럼
전체 지도가 먼저 필요한 질문이 있었다. Spring의 설정·Bean·DTO 비유와 실제 사고를
통한 서명 목적 설명도 해당 문답에서 효용이 관찰됐다. 동시에 PR #7의 본문에는
과거 동작과 현재 동작이 함께 남아 있었고, PR #39의 국소적인 초기화 문제에는
긴 리뷰 설명이 필요한지 모기가 반문했다. 모든 마찰을 낯선 문법 하나로 묶지 않는다.

구간 B에서는 PR #8 노트의 실행 시점·입력 출처 누락을 고친 뒤에도 설명할 정보와
순서의 부담이 남았다. 짧은 문답으로 옮겨 목록의 역할부터 설명하고 `cur` 재할당과
목록이 가리키는 객체를 표로 나눈 뒤 이해했다는 반응이 있었다. 그러나 분량·순서·
반복 노출·대화 방식의 영향을 분리한 실험은 아니다. PR #44에서는 더 넓은 호출
경로를 구체 사건 하나로 보여준 트리가 좋다는 평가가 있었다. 따라서 모든 설명을
무조건 짧게 하거나, 모든 질문에 전체 지도를 먼저 주는 규칙은 만들지 않는다.

Python Tutor 실행 성공·PNG 삽입에 대한 긍정 반응·특정 표 뒤 이해 반응·커밋 읽기
사용감은 각각 범위가 다르다. 이를 코드 노트 전체의 만족이나 raw diff 독해 완료로
합치지 않는다. 별도의 새 사례 독립 적용은 이번 여덟 기록 모두에서 미관찰이다.

### 3.3 새 사례 적용

여덟 기록 모두 이름·값을 바꾼 별도의 독립 적용은 시행하지 않아 **미관찰**이다.
가상 장보기·Git `retry_limit`·Node 버전 교체·a와 b 객체 예시는 설명에 함께 제공됐다.
PR #8의 빈 줄 누락 질문은 실제 코드의 경계를 지적한 관찰이고, PR #45 커밋 읽기는
다른 자료를 스스로 읽은 사용감 보고다. 이를 별도 전이 시험 성공으로 바꾸지 않는다.

지연 후 보조물 없는 적용도 관찰하지 않았다. 이 미관찰을 해소하기 위한 퀴즈·복습·
추가 코드 사례를 다음 세션에 삽입하지 않는다.

## 5. 다음 세션에서 실제로 바꿀 것

1. **지금 답할 질문의 범위를 먼저 고르고, 필요한 전제를 그 자리에서 밝힌다.**
   사용자 사건과 화면·저장 상태 변화부터 시작한다. 국소 원인이면 필요한 코드 몇 줄과
   그 결과에 먼저 답하고, 여러 메모는 사건별 전체 순서와 첫 묶음만 보여준다.
   `recipes` 같은 자료의 역할, 값의 출처·주인, 실행 주체·시점은 해당 코드·그림 가까이에
   둔다. 누락을 고친다고 앞뒤에 별도 표와 해설을 계속 쌓지 않는다. 원문·깊은 설명의
   직접 요청은 우선하며, 매번 깊이 선택을 모기에게 넘기지 않는다.
2. **헷갈리는 관계에 맞는 표현 하나를 먼저 고른다.** 여러 함수·설정의 역할이 질문이면
   실제 값 하나의 텍스트 호출 트리와 필요한 담당 위치를, 값·참조·유지 여부가 질문이면
   대상의 역할을 밝힌 짧은 전후 표를 사용한다. 같은 실행 순서를 그림으로 반복하거나
   도구 채택을 목표로 새 화면을 연속 제작하지 않는다. 현재 읽는 화면에서 보이는 형식을
   고르고, 반응은 해당 대목에만 연결한다. 잘 맞지 않는다는 평가에는 더 길게 반복하거나
   확인 퀴즈를 붙이지 않는다. 기존의 반복 재조립 중단·인계 경계는 그대로 적용한다.

이번 인수인계에는 위 두 항목과 효용이 관찰된 사건·상태표·참조 표·호출 트리만 가져간다.
과거 가설, 미관찰 항목을 해소할 과제, 특정 시각화 도구의 채택 결론은 추가하지 않는다.
