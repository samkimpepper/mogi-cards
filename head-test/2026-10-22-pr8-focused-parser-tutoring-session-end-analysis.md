## 짧은 기록

- **처음 막힌 지점:** 그림이 메시지 입력 전의 준비인지, 입력 후 훅 실행 안의 문서 수집인지 불분명했다. R1의 ‘실비청구’가 입력 프롬프트인지 문서 제목인지도 명시가 부족했다. 이를 고치며 출처 표와 설명을 앞뒤로 추가했지만, 모기는 설명할 정보가 많고 순서가 부담스럽다는 외부 피드백에 동의했다. 짧은 문답으로 전환한 뒤에는 `recipes`가 여러 레시피를 담는 목록이라는 역할부터 분명하지 않았고, `append(cur)`가 객체 a에 추가하는지 목록에 추가하는지, 목록에 넣은 ‘cur’가 재할당을 따라 바뀌는지를 물었다. 문서의 누락과 이번에 설명한 프로그래밍 개념을 함께 기록하며 단일 인지 원인으로 합치지 않는다.
- **설명 추가 없이 바로 연결한 지점:** 모기는 노트에 `line.startswith("## ")`의 문서 형식 의존성을 이미 지적하고 린트·검사 스크립트를 제안했다. `in_goal`의 수집 범위 설명 뒤에는 별도 유도 질문 없이 빈 줄을 빼먹으면 어떻게 되는지 물었다. 또한 과외냥이의 “사람이 실수”라는 표현을 에이전트가 작성하는 문서라고 바로잡았다. 제목 형식에 대한 최초 의심과 빈 줄 위험 질문은 서로 다른 시점의 관찰로 구분한다.
- **설명·외부화 뒤 달라진 점:** 모기는 PNG를 Markdown에 붙여 노트 안에서 읽는 형식에 “굿굿”이라고 했지만, 이는 노트 전체의 이해·만족을 뜻하지 않는다. 문답을 질문 하나와 짧은 코드·표로 줄인 뒤, `cur`가 어느 문서 절의 객체를 가리키는지 보여준 표에 “표 좋다좋다!”라고 반응했다. 이후에도 참조 질문은 남아 있었고, a·b 두 객체와 재할당 전후 표를 설명한 뒤에야 “아 이제 이해됨”이라고 말했다. `in_goal` 표 뒤에는 목표 표현 구간에서 `kw`에 단어를 더한다고 재진술하고 빈 줄 누락 위험을 제기했다. 각 반응을 해당 대목에만 연결하며 모든 파서 문법의 이해로 확대하지 않는다.
- **아직 미관찰이거나 다음에 확인할 점:** 이름·값을 바꾼 별도 새 사례의 독립 적용, 보조물 없는 지연 후 적용은 미관찰이다. 객체 내용을 수정하는 경우와 재할당하는 경우를 모기가 독립 사례로 비교한 결과도 없다. 후반에는 Python 문서 수집을 다뤘으며 Bash 판정·고장 사본 시험의 추가 독해는 분리해 남겼다. 문서 전체 완독·전체 PR 이해·머지 준비를 확인하지 않았고, 이를 해소할 자동 퀴즈·복습 과제로 넘기지 않는다.

## 학습 마찰·재확인·새 발견

### 정확한 명시와 읽을 분량의 선택은 각각 필요했다

> “소제목들에서 이게 언제 어느시점에 누구에의해 실행되는지가 명시가 안되어있어서임”

> “R1의 실비청구 이거는 내가 입력한 프롬프트인거임?”

누락된 실행 주체·시점·값의 출처를 밝히는 수정은 필요했다. 그러나 이를 여러 출처 표와 반복 설명을 더하는 방식으로 고친 뒤에도, 모기는 긴 설명을 스스로 걸러 읽어야 하는 부담에 관한 외부 피드백에 동의했다. 필요한 정보는 해당 코드·그림 가까이에 놓고, 실제 질문에 필요한 한 주제만 선택하는 방식으로 전환하기로 했다. 그 합의와 과외냥이 답변은 모기의 요청으로 기존 노트 맨 위에 보존했다.

이 전환 뒤 짧은 문답이 이어지고 특정 표에 긍정 반응이 있었지만, 분량·설명 순서·반복 노출·대화 방식 중 어떤 요소가 독립적으로 효과를 냈는지는 분리하지 않았다. 모든 설명을 무조건 짧게 하거나 표만 사용한다는 규칙으로 바꾸지 않는다.

### 목록의 역할을 먼저 설명한 뒤 참조 관계를 다뤘다

> “아 recipes가 무슨역할인지 몰랐음ㅋ”

초기 설명은 ‘같은 객체를 가리킨다’는 관계에 집중했지만, 모기는 추가를 받는 `recipes` 목록의 역할부터 물었다. 목록·객체·변수의 역할을 먼저 분리하고, `cur → a`를 목록 항목도 가리키게 한 뒤 `cur → b`로 바꾸는 설명용 예시와 표를 제시했다. 이후 이해했다는 사용자 반응을 확인했다. 외부 피드백의 예시처럼 `append()`를 이미 안다고 가정할 근거는 없었으며, 실제 문답으로 필요한 설명 범위를 찾았다.

### 빈 줄 누락에 따른 수집 경계 문제를 발견했다

> “빈줄 빼먹으면 어쩌려고;”

`73f2b00`에서 추출한 실제 파서·단어 추출 정의를 설명용 문서에 실행했다. 목표 표현과 backtick 단어 `택배`가 들어 있는 메모 사이에 빈 줄이 있으면 실비청구의 `kw`에 택배가 없었고, 빈 줄이 없으면 추가됐다. 다음 `## ` 제목에서는 수집 상태가 초기화되어 다음 절의 목표 표현까지 이전 객체에 들어가지는 않았다. 전체 훅 안내 출력이나 실제 세션의 오안내는 이 재현에서 실행하지 않았고, 그 영향은 코드 기반 가능성으로 구분했다.

> “아냐 사람이 실수라니 ㅋ 에이전트가쓰는문서잖아옹”

모기는 문서 작성 주체를 정정하고 에이전트 작성 결과와 파서 사이의 형식 약속을 검사할 필요를 강조했다. [마스터 전달용 메모](../master-delivery-memos.md)의 2026-10-22 todo-ops PR #8 항목에 재현·판독 SHA·한계·정정을 기록했다. 모기가 전송을 요청한 뒤 양쪽 주소를 확인하고 투두냥 Run으로 `msg_6302b319b62b`를 한 번 보냈다. 전송 접수는 확인했으며, 이 일지 작성 시점에 읽음·인수·린트 구현 완료는 확인하지 않았다.
