# 세션 종료 이해 관찰 — 원작자 권한·Storage·코어 인터뷰 리허설

날짜: 2026-08-14

## 오늘 조건

- **도메인 친숙도:** MOGUI 제품 정책·사용자 경험은 높음. PostgreSQL RLS·트리거는 중간 이하. Supabase Storage 내부 메타데이터·객체 수명주기와 인터뷰 진행은 낮음 또는 첫 실전 리허설.
- **세션 길이:** 정확한 wall-clock은 미측정. 대화 로그상 사용자 발화 약 60개로, 원작자 권한 → X 소유권 연결 → RLS → 이미지 사본 → Storage 이식성 → 트리거 → 인터뷰 리허설까지 이어진 장시간·다주제 세션.
- **컨디션:** 초중반에는 적극적으로 설계 모순을 추적하고 결정을 내림. 후반 리허설에서 `헥헥.. 이정도면됐나? 힘들다`고 피로를 명시함. 피로 명시 뒤의 생략·종료 판단은 독립 추론 실패로 채점하지 않음.
- **관찰 성격:** 통제된 A/B, 동급 난도, 지연 재검사를 하지 않은 비통제 세션 종료 관찰. 지능·인지능력·의학적 상태의 판정이 아님.

## 2. 암묵 슬롯 코딩

## 3. 기존 가설에 대한 지지와 반박

기존의 좁은 가설은 “암묵적 참조와 압축된 상태 전이가 컨텍스트 구성 비용을 높이고, 행위자·시점·전후 값의 정확한 외부화가 추론을 돕는다”이다. 더 강한 “일반적 작업기억 저하가 전반적 추론의 핵심 병목” 가설은 별도로 둔다.

### 지지 증거

1. **행위자·이벤트 바인딩이 겹친 C1:** `created_by`, `owner_uid`, `author_handle`, 원작자, 등록자, evidence 선택 시점이 겹치자 컬럼 역할과 자기등록 여부를 다시 물었다. 등록 시점과 evidence 선택 시점을 분리한 뒤에는 “신규 미검증 사용자의 등록 마찰은 줄지 않는다”는 구조를 유지했다.
2. **정책의 전후 상태가 겹친 C3:** `USING(true)`의 존재, 새 `hidden_at IS NULL` 정책 추가, permissive OR, 기존 정책 drop을 한꺼번에 유지하는 동안 초기 답을 고쳤다. `true OR 조건`과 drop 전후를 외부화한 뒤에는 기존 정책 제거 필요를 재진술했다.
3. **테이블·사본·provenance가 겹친 C4:** 부모·자식 RLS, 대표사진 승격, URL 값 복사와 FK 포인터를 분리하기 전 재질문이 집중됐다. 세 층을 분리한 뒤에는 URL 복사의 취약성과 X CDN 직접 참조를 다음 위험으로 연결했다.
4. **이벤트·시스템 경계가 겹친 C7~C8:** BEFORE/AFTER, SQL/API, metadata/bytes, fix1/fix2/sw-u4r가 같은 `storage 정리`라는 말에 묶이자 원인과 시점이 교환됐다. 상태 순서로 풀었을 때 fix2를 “현재 PR을 마무리하기 위한 봉합”으로 재구성했다.
5. **세션 길이와 조건 수:** 후반으로 갈수록 #513 권리, 임시 SQL, pending, 후속 Storage API, Kotlin 이식성까지 동시에 유지해야 했고 C7~C8의 재질문이 늘었다. 이는 이전 예측 3과 일관된다. 다만 피로와 기술 비숙련이 함께 있어 인과 분리는 불가하다.

### 반박 증거

반박 증거는 0개가 아니다.

1. **긴 세션에서도 상위 구조 유지:** C5에서 PR 번호는 흔들렸지만 “#513 범위를 키우지 않고 끝낸 뒤 Storage 전환을 별도 phase로 즉시 진행한다”는 의존 순서를 정확히 재진술했다.
2. **질문이 실제 결함을 발견:** evidence 예외가 신규 등록 마찰을 줄이지 못한다는 점, `created_by` 변조 위험, X OAuth scaffold의 목적 불일치, X CDN 직접 참조, `storage.objects` 직접 SQL 삭제의 공식 비지원성을 질문이 드러냈다. 재질문을 조건 손실로만 해석할 수 없다.
3. **새 제약의 독립 연결:** Kotlin Spring 이전 계획을 떠올려 Supabase 전용 URL 종속 위험을 스스로 제기했고, provider-neutral `object_key` 계약으로 후속 범위를 바꾸었다.
4. **근접한 새 추론:** C7에서 `RETURN NULL`을 제거하면 되는지 물은 것은 정확한 수정 `RETURN OLD`와 한 단계 차이였다. 트리거 반환 규칙을 몰랐지만 인과 사슬의 문제 지점은 맞췄다.
5. **낮은 슬롯에서도 진행 실수 발생:** C9~C10은 암묵 슬롯 합계가 4로 낮지만 선택지 심기와 probe 생성 중단이 있었다. 이는 컨텍스트 바인딩만으로 모든 오류를 설명하지 못하며, 첫 인터뷰 진행 경험·사회적 대화 습관·즉석 질문 생성 부담이라는 별도 요인을 지지한다.
6. **높은 슬롯이 항상 실패를 만들지 않음:** C1·C4의 복잡한 대화 뒤에도 원작자/등록자 구분과 부모/자식 정책 분리를 재구성하고 실제 제품 위험을 추가로 찾았다.

### 잠정 판정

- **컨텍스트 구성 비용 가설:** 부분 지지. 특히 같은 명사가 여러 시스템·시점에 재사용될 때 재질문이 집중됐다.
- **바인딩 가설:** 부분 지지. actor/table/event/phase를 명시하면 회복이 빨랐다.
- **일반적 작업기억 저하 가설:** 지지 불충분. 긴 세션의 상위 결정 유지, 모순 발견, 새 제약 전이가 반박 증거다.
- **질문 횟수를 실패 지표로 쓰는 방식:** 반박됨. 오늘 질문 여러 개가 실제 설계·문서 결함을 발견했다.

|---|---|---|---|---|
| C1 | actor·column·등록/선택 시점 바인딩 비용 | 높음 | 처음 보는 귀속 스키마와 `author_handle` 용어 자체의 지식 공백 | 높음 |
| C2 | 과거 결정·현재 결정과 `첫번째` 참조 복원 비용 | 낮음 | 실제 정책 결정의 큰 비용과 정체성 원칙을 숙고한 정상적 망설임 | 높음 |

## 종료 기록

- 오늘 가장 좁게 지지되는 설명: **암묵적 actor/table/event/phase가 겹치면 컨텍스트 구성 비용이 증가하지만, 재질문의 상당수는 새 도메인 지식·실제 설계 결함·정상적 의사결정 확인으로도 설명된다.**
- 가장 강한 반박: 낮은 슬롯의 인터뷰 문항에서도 진행 실수가 났고, 높은 슬롯의 기술 대화에서는 실제 모순과 이식성 제약을 독립적으로 찾았다.
- 외부화 효과: 상태 순서와 시스템 층 분리 뒤 회복 사례는 있으나, 동급 비교가 없어 크기와 인과는 판정 불가.
- 지연 후 유지: #513→Storage 순서와 `USING(true)` 교정은 여러 주제 뒤 유지된 정황이 있으나 지연 시간을 통제하지 않아 정식 판정 불가.
- 다음에 구분할 가장 작은 관찰: 익숙한 제품 정책과 낯선 DB 규칙 각각에서 암묵 슬롯 수를 비슷하게 맞춘 짧은 새 사례를 하나씩 사용해, 질문 유형이 슬롯 수보다 도메인 지식에 더 잘 따라가는지 본다.
