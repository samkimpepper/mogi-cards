## 1. 이게 왜 필요했나 `[READ]`

- `[READ]` 네가 물었던 "Memory.md 분리 잘 되고 있는지 측정" 은 사실 이미 설계돼 있었다 — 라우터 hook 에 걸린 반증 계약 M-010 이 판정 기준 (매칭 세션의 팩 실제 Read / 비매칭 주입 0 / hook 스프롤) 을 정의해뒀는데, **판정을 실행할 도구가 없었다.** 이 PR 이 그 도구다.
- `[READ]` 데이터 소스는 travelog 가 아니라 **세션 JSONL 아티팩트** — Claude Code 가 모든 세션을 자동 전량 기록하는 파일. hook 이 주입한 문구 원문과 모든 Read 툴콜 (파일 경로 포함) 이 남아서, "주입이 떴나 → 그 뒤 팩을 읽었나" 를 기계로 셀 수 있다. travelog 는 선별·서사, JSONL 은 전수·집계 — 보완 관계다.

## 2. 첫 실측이 말해주는 것 `[READ]`

- `[READ]` 맥북 36세션 baseline: 주입 0건 (hook 8/6 머지, 마지막 세션 8/1 — 예상대로). 대신 **소급 상한 23건** — "hook 이 그때 있었다면 주입이 떴을 세션" 이 23건이라는 건 라우팅 표가 실작업 패턴을 실제로 커버한다는 뜻이다. 순응률 판정은 라우터 이후 세션이 쌓여야 하고, 본진은 WSL2 (냐옹이 쪽) 데이터다.
- `[READ]` hook 스프롤 없음 — 팩 라우팅은 라우터 1개뿐 (11개 hook 전수 확인). M-010 세 번째 기준은 지금도 통과.

## 3. 측정 도구를 측정한 이야기 `[READ]`

- `[READ]` Codex 교차 리뷰가 **도구 자체의 P1** 을 잡았다: 팩별 첫 Read 순번만 기억해서 "주입 전에도 읽고 후에도 읽은" 세션을 미순응으로 오판 — 측정기가 순응률을 실제보다 낮게 보고하는 버그. 측정 도구가 틀리면 M-010 판정이 오염되니 (낮은 순응률 → "팩 전문 주입으로 승격" 오결정) 머지 전에 잡는 게 맞았다. 수정 후 self-test 33건으로 회귀 방지까지 걸었다.
