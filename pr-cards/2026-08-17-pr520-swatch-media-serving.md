## 이 PR이 하는 것 (골격)

- **어댑터 일원화**: 화면의 사진 URL 조립을 한 모듈로 — 공개 = 자체 사본 public URL, 숨김 소유자 열람 = 서버 발급 서명 URL(600초), 사본 없으면 기존 X CDN URL 폴백(전환기)
- **이중 버킷 수명주기**: private 버킷 신설 + A레인이 기록만 하던 큐를 드디어 소비(숨김 = public→private 이동, 해제 = 복귀, 삭제 = 제거) — #513의 비공식 SQL 직접 삭제 폐기. 숨김 후 잔존 노출 창 = CDN 캐시 3600초 + 배치 15분(문서화된 수용 경계)
- **대표사진 관계·재선정**: shade_images가 URL 문자열 대신 사본 대장 FK 참조 + 대표사진 원본이 숨김·삭제되면 같은 트랜잭션에서 차순위 자동 선정(사다리 등급 우선·동급 선착순). 숨김 해제는 자리 복원이 아니라 후보 풀 재진입
- **화면 전환**: 탐색의 "이미지 없으면 숨김" 필터 제거 → 사다리 표시(사진 > 색상칩 > 회색칩 '색상 정보 없음'), 홈 내 화장품의 공용 대표 fallback은 격리 갈래('공용 대표 · 내 발색 없음' 배지, 색상칩 번복 = 상수 1개), 죽은 카드 전 표면 비노출 + 원작자 복구 배지
- **ADR D-127 승격**

## fix1이 고치는 것 (교차 리뷰 확정분 — 왜 아직 머지 불가인가)

1. [높음] 핵심 화면의 공용 대표가 어댑터를 **우회**해 생 URL을 쓰고 있었다 — 서빙 전환이 사실상 미완이었던 구멍
2. [높음] 복사 진행 중에 숨기면 완료된 사본이 공개 버킷에 영구 잔류 (A레인 기적용 마이그의 잠복 결함 — 신규 마이그로만 수리)
3. [높음] 사진 교체 두 번째부터 대표 회수가 끊기는 관계 단절
4. [높음] Storage 일시 오류를 "객체 없음"으로 오판해 공개 객체 잔류 가능
5~7. [중간] 재시도 예산 굶김 · 판정 RPC 장애 시 죽은 카드 재노출(fail-open→closed) · URL 전역 매칭 오연결
8. [낮음] 복구 버튼 실패 시 재시도 불가 UX

반증 통과(안심 재료): 재선정 원자성("대표 없음" 창 없음) · 서명 URL 타인 발급 경로 없음 · private 버킷 여는 정책 0 · 범위 준수.

## 이해 체크 골격 (퀴즈 재료 — fix1 완료 후 정식)

- 숨김을 눌러도 잠깐 보일 수 있는 창이 왜 존재하고, 어디까지가 승인된 경계인가
- 재선정이 "회수와 같은 트랜잭션"이어야 하는 이유 — 어기면 무엇이 보이나
- 숨김 해제가 "자리 복원"이 아니라 "후보 풀 재진입"인 것의 차이 — 어떤 경우에만 대표가 바뀌나
- fail-open과 fail-closed — 판정 RPC가 죽었을 때 어느 쪽이 왜 옳은가
- 어댑터 우회 발견물(fix1-1)이 없었다면 출시 후 어떤 상태였겠나
