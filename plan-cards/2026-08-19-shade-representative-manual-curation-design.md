# 카드 — shade 대표사진 수동 큐레이션: 설계 확정 (sw-djc, A안)

작성: 냐옹이(office, Gen 11), 2026-08-19. 브레인스토밍 → 모기 A안 확정. 다음 단계 = 워커 계약 작성.

## 무엇을 왜

#523(어드민 shade 갤러리 폐기)이 대표사진을 손으로 고르는 유일한 UI를 함께 지웠다(그 버튼은 브라우저 직접 UPDATE라 살렸어도 결함). DB에는 `manual`이 사다리 최상위로 살아 있는데(08-17 결정문 §1) **manual을 만들 입구가 없다** — 문고리 없는 문. 자동 사다리는 "대표가 비지 않게"만 보장하고 미관은 판단 기준에 없어서, 탐색 탭 첫인상이 등록 순서·사진 종류에 좌우된다(모기 발견 2026-08-19).

## 결정 골격 (A안)

- **성격**: 상시 운영 기능 (일회성 큐레이션 도구 아님 — 모기 확정).
- **DB — 신규 어드민 RPC 2개**, 기존 `set_shade_representative_image`(등록 경로 전용, manual 거부)는 불변:
  - `admin_set_shade_representative(shade, media)` — `admin_users` 게이트. `representative_source='manual'`로 지정. **공개 사진만 허용** — 숨김 사진 지정은 #513 경계 위반이라 거부.
  - `admin_clear_shade_representative(shade)` — 핀 해제, **같은 트랜잭션에서 자동 재선정**이 사다리로 채움(#520 재선정 로직 재사용, 복제 금지).
- **UI — 기존 어드민 영역(`app/src/features/admin/`)에 대표사진 섹션 신설**: shade 목록(현 대표 썸네일 + 소스 뱃지 + 후보 수) → 후보 그리드(그 shade를 매핑한 등록들의 **전체 공개 사진** — 자동 풀의 "첫 사진만" 제한은 자동 추정 금지 원칙 때문이고, 수동은 사람 눈이 판단하므로 넓힘, 모기 확정) → 클릭 지정/해제. 전부 RPC 경유, 직접 UPDATE 재도입 금지.
- **manual 상호작용은 신규 규칙 없음 — 기존 규칙 소비**: 자동 재선정·숨김 해제 재진입은 manual을 못 덮는다(D-099 가드가 마이그레이션에 실재, `representative_source <> 'manual'`); manual 사진 자체가 회수되면 재선정이 돈다(08-17 결정문 §2 마지막 줄, #520 구현 완료).
- **전환기 공백**: 후보 그리드는 사본 대장(`swatch_media`)에서 뽑는데 C레인 백필 전의 레거시 등록 사진(backup/ 원본 177)은 대장에 행이 없어 안 보인다. C레인 완료 시 소급 완성 — 화면에 안내 문구 한 줄로 처리. **C레인 의존으로 이 기능을 막지 않는다.**

## 과외 검토 요청 포인트

- `admin_clear` 해제 직후 재선정이 뽑는 결과가 "직전 auto 상태 복원"과 다를 수 있다(그 사이 후보 풀 변동) — 이 감각이 어드민 관점에서 자연스러운가.
- 후보 그리드를 등록 전체 사진으로 넓히면, 비교 단체샷을 manual 대표로 고를 때 라벨 표시 계약(D-099의 fallback 라벨)이 manual에도 필요한가 — 지정은 사람이 했지만 화면 독자는 모른다.
- 전환기 공백 안내 문구가 C레인 완료 후 제거될 일감으로 등재되는가(잊힌 안내 문구는 거짓말이 된다).
- 신규 RPC 2개의 SECURITY DEFINER 표면 — search_path 고정·권한 REVOKE 관례(#504)와 정합한지.

## 이해 체크 골격 (과외냥이용 — 주관식 재료)

- 왜 기존 RPC에 manual을 열지 않고 어드민 전용 RPC를 신설하는가 (권한 표면 분리)
- 숨김 사진을 manual로 지정하면 어떤 경계가 깨지는가 (#513)
- 핀 해제 시 자동 재선정을 같은 트랜잭션에서 돌려야 하는 이유 (대표 없음 창)
- 후보 그리드가 C레인 전까지 불완전한 구조적 이유 (사본 대장과 레거시 URL의 시대 차)
