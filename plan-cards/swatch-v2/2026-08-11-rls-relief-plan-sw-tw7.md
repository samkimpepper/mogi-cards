# 카드 — RLS 절감 트랙 계획 (sw-tw7, 착수 전 설계 카드)

작성: 냐옹이 Gen 5, 2026-08-11. 원문 SSOT: sw-tw7 이슈 + gen5-kickoff 현황판 + 이 카드의 브레인스토밍 대화. PR 아직 없음 — **착수 전 계획 이해용 카드**다.

## 1. 왜 하는가 (네가 이미 한 결정의 이행)

- 너는 Supabase 이주 대신 **비용 절감**을 택했다(pre-launch-migration-brake, 네 상시 지시). 이 트랙이 그 절감의 실체다.
- 네 고통 3개를 직접 겨눈다: ① 마이그 PR 검증 공포(최악) ② 정책 파악 불가 ③ 새 기능마다 우회 설계 마찰.
- 오늘 P0 회귀가 프로덕션을 안 망친 건 제도가 아니라 **네가 db push를 미뤄둔 운**이었다. 그 운을 제도로 바꾸는 게 목표.

## 2. 계획 골격 (A안, 네가 승인)

산출물 3개, 순서대로:

1. **CI 하네스** (워커 PR 1) — 마이그레이션 건드리는 PR마다 CI가: 로컬 Supabase 스택 기동 → 마이그 147개 전량 적용 → 기존 테스트 스위트 ~20개 + PR #498 구조 검증 쿼리 5개 실행. 지금은 이걸 워커 성실성에만 의존한다. 오늘 P0(sw-drw)는 이 잡이 있었으면 머지 전에 잡혔다.
2. **정책 스냅샷 자동 생성** (워커 PR 2) — pg_policies·grants를 사람이 읽는 표로 뽑아 저장소에 커밋. 마이그 PR의 diff가 곧 "정책이 이렇게 바뀐다" 리뷰 자료가 된다. CI가 스냅샷 낡음을 검출. 손으로 쓰는 정본 표는 안 만든다(네 선택 — 어차피 안 읽을 물건 유지비 제거).
   - **과외냥이 지적 반영(2026-08-11)**: 스냅샷이 최신이라는 것과 네가 읽었다는 건 다르다. 그래서 생성기가 **변경분 사람말 요약 한두 줄**("누가 어느 테이블에서 뭘 할 수 있게/없게 됐는지")을 같이 뽑고, CI가 그걸 **PR 코멘트로 자동 게시**한다 — 머지 버튼 옆에 떠서 네 의지가 필요 없다. 긴 표의 기술 검증은 CI+교차 리뷰 몫, 너는 그 한두 줄만 본다(네 확인, 환류 메모함 기록).
3. **원격 적용 절차 런북** (마스터가 swatch-ops에 직접) — db push 전·후 검증 순서 표준화 + 마이그 계약에 원격 재실행 검증 절 필수화(sw-o4s). "미뤄둔 창"의 제도화.

레인 구조: ①②는 같은 인프라라 **한 워커가 순차로**(PR 두 장 = 카드 두 장). 병렬 안 하는 이유 = 형제 미머지 PR은 교차 리뷰가 못 본다(4세대 교훈).

## 3. 범위에서 뺀 것

- **RLS 좁히기**(sw-tw7 원안, user_profiles self_update): 착수 게이트("유저 직접 수정 필드가 실제 추가될 때")가 아직 안 열림. CI 하네스가 깔린 뒤에 하면 훨씬 안전해서 게이트 뒤에 그대로 둔다. 착수 시 보안 세션 위임 대상.
- **어드민 판별 재설계**(sw-qd5): 권한 모델 대화라 sw-c2p(원작자 직접권) 레인과 묶어서 별도 브레인스토밍.
- **프로덕션 DB 자격증명을 CI에 넣지 않는다** — 이미 확정된 결정. CI는 프로덕션 상태가 아니라 마이그의 성질을 검사한다.

## 4. 네가 결정할 것

- **CI 필수 체크화**: 빨간불이면 머지 버튼이 잠기게 GitHub branch protection에 박을지. 저장소 설정이라 네 손이 필요하다. 마스터 추천 = 필수화(검증 공포의 해독제는 "초록불이면 안심"). PR 1 머지 후에 결정해도 됨.
- 트랙 착수 승인 (계약 작성 → 디스패치 게이트).

## 5. 위험한 가정

- "CI 통과 = 안전"의 경계: CI 로컬 스택은 마이그의 성질을 검사하지, **프로덕션의 현재 데이터 상태**는 못 본다. 데이터 의존 확인과 앱 동선 확인은 여전히 push 절차(산출물 ③)와 사람 몫이다.
- 스냅샷은 실물이지 **의도가 아니다** — "왜 이 정책인가"는 여전히 마이그레이션 주석과 계약 문서에 있다.

## 6. 이해 체크 골격 (과외냥이가 살 붙일 것)

- 오늘 P0 회귀는 왜 CI가 아니라 사람이 잡았나? 이 계획의 어느 조각이 그 구멍을 막나?
- 정책 스냅샷이 마이그 PR 리뷰를 어떻게 바꾸나? 스냅샷이 못 담는 건 뭔가?
- RLS 좁히기를 왜 지금 안 하나? 언제 하나?

## 7. 안 읽어도 되는 세부

- CI 잡 트리거·러너 구성, 스냅샷 생성 스크립트 설계 — 계약(swatch-ops/contracts/)에 적힐 것. 카드 갱신은 PR 나올 때.
