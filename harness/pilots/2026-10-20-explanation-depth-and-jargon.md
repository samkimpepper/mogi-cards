# 필요한 설명 깊이 선택 — jargon·diff·배경 공부를 자동으로 늘리지 않기

모기가 PR을 읽으며 ‘이 용어를 공부해야 하나, diff를 봐야 하나, 설명을 쉽게 고쳐야 하나’를 매번 판단해야 했다고 알렸다. 과외냥이가 필요한 첫 설명의 깊이를 먼저 골라 그 부담을 줄여보는 **다음 자연 발생 PR·리뷰 설명 3건의 한시 파일럿**이다. 모기가 더 깊게 공부하려는 선택은 그대로 따른다.

## 적용할 때

- 적용 전 이 문서의 `status`와 횟수를 확인한다. `status: pilot`이고 `completed_cases < planned_cases`인 동안만 적용한다.
- PR·코드리뷰에 관한 하나의 독립된 사용자 사건·수정 이유를 한 건으로 센다. 같은 대목의 재설명·후속 질문은 같은 건이며, 횟수를 채우려고 장면을 만들거나 쪼개지 않는다.
- 오늘 PR #39 설명은 계기이며 소급 적용으로 세지 않는다. 일반 질문·필기노트 작성·운영 작업에는 자동 확대하지 않는다.

## 첫 설명 전에 과외냥이가 고를 것

관련 원문·diff·계약은 먼저 확인한다. 그 뒤 **이번 변경을 이해하거나 선택을 판단하는 데 필요한 설명**을 고른다. 자료를 읽은 범위와 모기에게 먼저 보여줄 분량을 구분한다.

| 필요한 것 | 첫 설명 방식 | PR #39에서의 예 |
|---|---|---|
| 용어가 가리키는 동작·대상 | 사용자 말로 풀고, 원래 이름은 검색·로그 연결에 필요할 때 가까이 한 번 붙인다 | `stale` → 지난 몫 취소, template → 반복 원본, instance → 그날 몫 |
| 국소적인 코드 원인 | 사용자에게 생기는 결과와 원인부터 짧게 설명한다. 초기화 위치·조건식처럼 코드가 더 직접적이면 실제 전후 몇 줄을 곁들인다 | P2: 멈춤 변수가 원본마다 초기화됨 → 바깥 반복문 앞으로 이동 |
| 실행 순서·여러 대상의 관계가 선택 이유를 좌우함 | 구체 값 하나로 주체·시점·대상을 표에 펼친 뒤 필요한 연결 코드만 붙인다 | P1: 앱 비교 기준을 잡는 시점과 DB 날짜 확인 순서 |

- **실패 영향의 중요도와 원인을 설명하는 데 필요한 길이는 따로 판단한다.** 중요한 문제여도 원인이 단순하면 짧게 설명하고, 사용자에게 생기는 영향·남은 미확인은 분명히 남긴다.
- jargon을 만났다는 이유만으로 주변 기술·역사를 모두 공부하게 하지 않는다. 배경이 현재 사건을 설명하는 데 필요하면 먼저 그 연결을 밝히고 필요한 부분만 설명한다. 모기가 기술의 의도·역사를 직접 물으면 그 질문을 따른다.
- 함수명·시험 이름·재현 전문·작업 이력은 필요한 첫 설명과 구분한다. 경로·SHA·검증 근거는 짧게 연결하고 원문 링크를 남긴다. 이해에 필요한 전제나 실제 앱 미확인을 분량 때문에 감추지 않는다.
- ‘공부/코드/쉽게’ 중 고르라는 메뉴를 매 질문마다 모기에게 되묻지 않는다. 첫 설명을 제공한 뒤 모기의 질문·직접 요청에 맞춰 넓힌다. 깊이를 잘못 골랐으면 설명의 선택을 수정하고 모기의 능력으로 귀속하지 않는다.
- 설명 길이에 고정 상한을 두지는 않는다. 단순한 수정은 사용자 결과·원인·수정과 검증을 몇 문장으로 먼저 전달하는 것을 목표로 한다. 큰 흐름은 기존 스크래치패드 규칙처럼 나누며 확인 퀴즈를 필수로 붙이지 않는다.

## 실제 diff·검증과의 관계

- 모기가 코드·diff를 요청하면 바로 실제 원문을 보여준다. 과외냥이가 이해에 필요하다고 골랐을 때도 먼저 보여줄 수 있다. 원문을 보여줄 때 파일·판독 SHA와 실제 인용/설명용 예시를 구분한다.
- 이 파일럿은 실제 diff 판독을 생략하거나 모든 PR을 비유로만 설명하는 규칙이 아니다. 기존 raw diff 접촉 파일럿의 전체 파일 지도·원문 관찰 질문·샛길 선택을 이번 파일럿 때문에 매 답변에 추가하지 않는다. 과거 파일럿 원문은 보존한다.
- 검증 설명은 기존 가이드의 입력·시험 결과·실앱 미확인 구분을 유지한다. 과외냥이 재실행과 작성자·리뷰어 보고를 구분하고, 상세 이름·로그는 필요에 맞춰 연결한다.

## 건별 기록과 종료

한 건의 자연스러운 문답이 끝나면 아래를 `실행 기록`에 짧게 남기고 `completed_cases`를 1 올린다. 기록 때문에 대화를 끊거나 추가 질문·시험을 만들지 않는다.
