# 발견물 중복 확인 관문 파일럿

## 상태와 한 줄 목적

이 문서는 영구 운영 규칙이 아니라 **앞으로 자연 발생하는 발견물 후보 3건**에만 적용하는 임시 파일럿이다.

과외 중 같은 미결 원인이 다른 코드에서 다시 나타나는 것은 막지 않는다. 새 마스터 전달 메모를 쓰기 직전에 기존 열린 항목과 연결해, `동일 영향의 중복 전달`과 `기존 원인이 만든 새로운 영향`을 구분하는 것이 목적이다.

## baseline — 실행 횟수에 포함하지 않음

2026-08-20 PR #524 과외에서 self-thread 사진 중복을 새 정책 공백처럼 다시 전달한 뒤, 2026-08-18 PR #520 과외에서 이미 같은 원인을 발견해 운영 트래커 `sw-xvv`로 라우팅했다는 사실을 확인했다.

이 사건은 관문을 적용하기 전에 일어났으므로 실행 1회로 세지 않는다. 파일럿을 만들게 된 baseline으로만 둔다.

## 언제 실행하는가

다음 조건을 모두 만족할 때만 실행한다.

1. 과외 중 버그·개선거리·미결 질문 후보를 발견했다.
2. 제품 저장소를 고치지 않고 `master-delivery-memos.md`에 append하려는 순간이다.
3. 아직 prospective 실행 기록이 3건 미만이다.

질문을 받을 때마다, PR을 열 때마다, 세션을 시작할 때마다 선제적으로 실행하지 않는다. 발견물 후보가 없으면 이 문서를 읽지 않는다.

## 확인할 곳

발견물의 테이블·주체·이벤트·결과를 짧은 검색어 2~4개로 나눈 뒤 아래 순서로 읽기 전용 확인한다.

1. 현재 `master-delivery-memos.md`
2. 그 파일의 git 이력 — 처리 후 비워진 과거 원문까지 확인
3. `../swatch-ops/.beads/issues.jsonl`의 열린 운영 트래커 항목

정확한 단어 일치만으로 같은 문제라고 판정하지 않는다. 어느 테이블·행·값의 주인인지, 어떤 이벤트에서 무엇이 잘못되는지를 대조한다.

과거 세션 JSONL 전수 검색은 기본 관문이 아니다. 모기가 “전에 얘기했다”고 기억하거나, 위 세 곳만으로 동일성을 가릴 수 없을 때의 원문 복구 수단으로만 쓴다.

## 세 가지 판정과 행동

### A. 신규 원인 또는 기존 항목 없음

- 프리앰블의 원래 발견물 형식으로 `master-delivery-memos.md`에 append한다.
- 판독 SHA와 근거를 그대로 남긴다.

### B. 기존 원인 + 같은 영향

- 같은 내용을 새 발견물처럼 다시 append하지 않는다.
- 사용자에게 기존 이슈 ID·상태·과거 처리 근거를 알려준다.
- 기존 항목이 여전히 열린 채 재현됐다는 사실이 새 운영 증거라면, 그 증거만 별도 추가할 필요가 있는지 구분한다.

### C. 기존 원인 + 새로운 영향 또는 새로운 소비처

- “새 정책 공백”으로 복제하지 않는다.
- 기존 이슈 ID를 명시하고, 이번 코드에서 새로 드러난 영향·근거·판독 SHA만 delta로 append한다.
- 기존 항목이 있다는 이유만으로 새 버그 가능성을 닫거나 설명을 중단하지 않는다.

## 실행 기록

각 prospective 실행 뒤 아래만 append하고 `completed_runs`를 1 올린다. 발견물 자체를 메모하지 않은 B 판정도 관문 실행이므로 1회로 센다.

```text
### 실행 N — YYYY-MM-DD · 재료

- 후보: 무엇을 새 발견물로 쓰려 했나
- 검색: 현재 메모 / git 이력 / 열린 트래커에서 무엇을 찾았나
- 판정: A 신규 / B 같은 영향 / C 새 영향
- 행동: 새 메모 / 중복 생략 / 기존 이슈 delta 연결
- 마찰: 모기가 표현한 흐름 방해 또는 도움, 없으면 미관찰
- 오판 가능성: 표현 차이·근거 부족 등 남은 경계
```
