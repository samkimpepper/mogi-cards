# 코드 학습 노트 참조 완결성 감사 파일럿

## 상태와 한 줄 목적

이 문서는 영구 운영 규칙이 아니라 **조건에 맞는 코드 학습 노트를 다루는 과외 세션
3회**에만 적용하는 임시 파일럿이다.

과외냥이가 초안을 만든 뒤 별도의 읽기 전용 감사냥이가 정확한 SHA의 실제 소스를
독립적으로 읽고, 이미 내용을 아는 작성자만 복원할 수 있는 생략을 찾는다. 감사냥이는
문서를 고치지 않고 근거가 있는 누락 보고만 돌려준다.

## 카운트 규칙

- 한 과외 세션에서는 감사 대상 노트가 여러 개여도 최대 1회만 센다.
- 감사냥이의 완료 보고가 실제로 도착하고 과외냥이가 그 보고를 읽은 뒤에만
  `completed_sessions`를 1 올리고 `remaining_sessions`를 1 내린다.
- 적합한 노트가 없거나, 감사 작업이 시작되지 않았거나, 작업이 실패해 보고가 도착하지
  않으면 횟수를 차감하지 않는다.
- `completed_sessions: 3`이 되면 다음 세션부터 자동 실행하지 않는다. 세 기록을 모기와
  검토하기 전에는 영구 규칙이나 상시 커스텀 에이전트로 승격하지 않는다.
- 모기가 중단을 선언하면 남은 횟수와 관계없이 즉시 멈춘다.

## 언제 실행하는가

아래 중 하나에 해당하는 `code-diff-notes/` 초안을 새로 만들거나 크게 고친 세션에만
실행한다.

- SQL·repo·UI·테스트처럼 여러 파일 층의 역할을 한 흐름으로 연결한다.
- 두 개 이상의 테이블·행이 상태 전이에 참여한다.
- 지정·해제·복귀·fallback·재선정·동시성처럼 조건에 따라 결과가 갈린다.
- 파일 역할 지도, 예시 상태, `모기 박스`, 한 줄 요약에 생략된 참조가 생기기 쉽다.

간단한 한 파일 diff, 철자·문구 수정, 일반 질문 답변에는 실행하지 않는다. 모든 문장을
감사하는 상시 문장 교정기도 아니다.

## 감사 입력

과외냥이는 새 문맥의 읽기 전용 감사냥이에게 다음을 명시한다.

1. 감사할 초안의 정확한 경로
2. PR 또는 fix의 base·HEAD SHA
3. 판독할 실제 소스 파일 경로
4. 제품·운영 저장소와 `mogi-cards` 모두 수정하지 말라는 경계
5. 감사 범위와 아래 고정 출력 형식

감사냥이는 현재 checkout의 우연한 상태로 추측하지 않는다. 초안에 적힌 판독 HEAD의
blob을 `git show <SHA>:<path>`처럼 읽어 근거를 고정한다. 근거를 찾지 못하면 설명을
완성하지 않고 `미확인`으로 표시한다.

## 감사 범위

다음 구역만 우선해서 본다.

- 변경 파일 역할 지도
- 예시 상태와 이벤트 전후 설명
- `모기 박스`의 질문과 힌트
- SQL → repo → UI → 테스트처럼 층을 건너는 연결 문장
- 마지막 한 줄 요약

raw diff 자체, 전체 파일명 목록, frontmatter, 날짜 같은 메타데이터는 기본 감사 대상이
아니다. 다만 설명이 raw diff와 반대로 적혔으면 사실 불일치로 보고한다.

## 참조 완결성 판정

`지정`, `해제`, `복귀`, `변환`, `반환값`, `두 개`, `해당`, `결과`, `처리한다` 같은
단어는 검색 후보일 뿐 자동 반려 사유가 아니다. 감사냥이는 각 문장에서 필요한 범위의
다음 슬롯이 실제로 묶여 있는지를 본다.

```text
어느 테이블·행·컬럼인가
→ 그 값이나 동작의 주인은 누구인가
→ 어떤 이벤트와 조건인가
→ 변경 전 값·행은 무엇인가
→ 변경 후 값·행은 무엇인가
→ RPC·함수·파일처럼 고유한 대상 이름은 무엇인가
```

표, 파일 역할 지도, `모기 박스`, 캡션은 따로 훑어 읽히므로 그 항목 안에서 참조가
완결돼야 한다. 이어지는 해설 문단은 바로 앞 문장에 정확한 테이블·행·이벤트가 이미
고정돼 있으면 같은 이름을 기계적으로 반복하지 않아도 된다.

## 감사냥이 고정 출력

전체 문서를 자유롭게 재작성하지 않는다. 발견마다 아래 한 묶음만 반환한다.

```yaml
- 초안 위치: <소제목·문장>
  모호한 원문: <그대로 인용>
  literal하게 남는 질문: <문장만 읽으면 정해지지 않는 대상·조건>
  빠진 슬롯: <대상 | 테이블·행 조건 | 컬럼 | 이벤트 | 변경 전후 | 고유명사>
  소스에서 확인한 사실: <근거로 확인한 최소 사실>
  최소 교체안: <빠진 참조만 보충한 문장>
  근거: <HEAD SHA · 파일 경로 · 함수/심볼 · 줄 위치>
  판정: 확인됨 | 미확인
```

발견이 없으면 `PASS — 감사 범위에서 참조 누락 없음`과 실제 판독한 SHA·파일만
반환한다. “모기가 물을 가능성이 높다”처럼 모기의 미래 반응이나 능력을 추측하지 않는다.

## 과외냥이의 후처리

1. 감사 보고를 실제 소스와 다시 대조한다. 감사자의 대체 문장을 그대로 복사하지 않는다.
2. 확인된 누락만 최소 수정 후보로 삼는다. 문단 전체를 다시 쓰거나 난도를 갑자기 낮추지 않는다.
3. 의미·정책 판단이 달라지는 수정은 모기에게 보고한 뒤 결정한다.
4. 감사냥이는 파일을 수정하지 않는다. 파일 수정과 최종 문장 책임은 과외냥이에게 있다.
5. 실행 뒤 이 문서의 카운터와 아래 기록을 갱신한다.

## 종료 뒤 판단할 것

- 다중 파일 역할 지도와 상태 전이의 빠진 대상을 실제로 잡았는가
- `모기 박스`를 literal하게 읽을 때 생기는 해석 부담을 줄였는가
- 근거 재확인과 조정 비용이 감당 가능한가
- 감사자의 최소 교체안이 과도한 재작성으로 번지지 않았는가
- 영구 규칙, 선택 모드, 폐기 중 무엇이 맞는가
